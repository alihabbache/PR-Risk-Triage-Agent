          📐 Product Architecture & Algorithm Specification
          Technical Spec
        
    

        
    
          
    1. Problem Definition
    
          
    
            Code reviewers at scale cannot immediately discern high-risk, production-breaking PRs from routine or cosmetic PRs.
            Reviewer fatigue causes mission-critical bugs (e.g. race conditions in checkout, unverified JWT signatures) to be rubber-stamped,
            while simple doc and test PRs suffer unnecessary review lag.
          
    

          
    2. Core Tri-Pillar Scoring Formulation
    
          
    The PR Risk Triage Agent computes a composite score $S \in [0, 100]$ using a calibrated weighted formulation:
    
          
    Risk_Score = (0.40 * Blast_Radius) + (0.35 * Incident_Correlation) + (0.25 * Author_Risk)
Safety Guardrail: IF Overlaps(SEV-1 Incident Files) => Floor Score = MAX(Risk_Score, 55.0)

    4. Implementation Architecture
    
          
    
            • Client-Side Engine: Runs directly in browser via GitHub Pages for demonstration and simulation.
    
            • GitHub Action CI/CD: Executes via standard Python CLI during pull_request event trigger.
    
            • Self-Contained: Leverages repository metadata and GitHub API tokens without requiring external databases.
